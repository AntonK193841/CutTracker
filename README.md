# CutTracker

**Система учета и расчета раскроя листового металла**

CutTracker — веб-приложение для инженеров судостроительного производства. Система позволяет загружать спецификации деталей, рассчитывать их размещение на металлическом листе, оценивать количество отходов и вести учет материалов на складе.

Проект демонстрирует практическое применение **Python, FastAPI, PostgreSQL, React, REST API, ООП, алгоритмов оптимизации и автоматизации Excel**.

---

## О проекте

При производстве деталей из листового металла инженер должен определить:

* какие детали необходимо изготовить;
* какие материалы доступны на складе;
* как разместить детали на листе;
* сколько материала будет использовано;
* сколько материала останется в виде отходов.

В традиционном процессе часть этих операций может выполняться вручную в Excel с использованием VBA/VBS-макросов.

CutTracker автоматизирует этот процесс и переносит основные данные и расчеты из Excel в централизованную систему.

# Алгоритм раскроя

Для демонстрационной версии используется простой жадный алгоритм размещения.

Перед расчетом детали сортируются по размеру. После этого алгоритм последовательно пытается разместить каждую деталь на листе.

Для каждой детали проверяются две ориентации:

```text
width × height

height × width
```

Если деталь не помещается в текущую строку, выполняется переход на следующую.

Результат расчета содержит:

* координаты размещения;
* размеры размещенной детали;
* информацию о повороте;
* площадь листа;
* площадь деталей;
* площадь отходов;
* процент использования;
* список неразмещенных деталей.

Алгоритм является демонстрационным. В промышленной версии его можно заменить более продвинутым nesting-алгоритмом с поддержкой сложных геометрических контуров.

# ООП

Расчетная логика отделена от HTTP и базы данных.

Основные классы:

```text
Sheet
 │
 └── описывает металлический лист

Part
 │
 └── описывает деталь

Placement
 │
 └── описывает положение детали на листе

NestingCalculator
 │
 └── выполняет расчет размещения

NestingResult
 │
 └── содержит результат расчета
```

Это позволяет независимо тестировать алгоритм и использовать его не только через REST API.

# Excel Importer

Импортер находится в отдельном каталоге:

```text
importer/
```

Он принимает Excel-файл со спецификацией:

| drawing_number | name         | width | height | quantity | material_id |
| -------------- | ------------ | ----: | -----: | -------: | ----------: |
| DWG-001        | Bottom Plate |   500 |   1000 |        4 |           1 |
| DWG-002        | Side Plate   |   300 |    800 |        6 |           1 |
| DWG-003        | Bracket      |   200 |    300 |       12 |           1 |

Процесс обработки:

```text
Excel
  │
  ▼
Чтение файла
  │
  ▼
Проверка колонок
  │
  ▼
Валидация данных
  │
  ▼
SpecificationPart
  │
  ▼
HTTP POST
  │
  ▼
CutTracker API
```

Тестовый файл находится в:

```text
data/specification.xlsx
```

Одна из целей проекта — показать переход от типичного legacy-процесса к современной архитектуре.

Условный старый процесс:

```text
Excel
   │
   ▼
VBA/VBS
   │
   ▼
Расчет
   │
   ▼
Excel
```

В CutTracker:

```text
Excel
   │
   ▼
Python Importer
   │
   ▼
REST API
   │
   ▼
PostgreSQL
   │
   ▼
Web Application
```

При этом инженер по-прежнему может использовать привычный Excel-шаблон как исходный формат.

```text

              │

       └──────┬──────┘
              ▼
       Расчет раскроя
              │
       ┌──────┴──────┐
       ▼             ▼
   Использование   Отходы
   материала
              │
              ▼
       Web-интерфейс
```

Проект демонстрирует разработку прикладного инженерного ПО с использованием REST API, реляционной БД, ООП, алгоритмов, автоматизации Excel и современного web-интерфейса.
